# Tyan S8030

AMD SP3, one socket, EPYC 7002 (Rome) or 7003 (Milan). Status: board data
and policy; not booted with fstart yet.

One board id, `tyan-s8030`, and one build for both generations: the
platform's `rome` and `milan` features are enabled on its dependency, and
the reset image picks the generation from the CPU at runtime. Each half
keeps the vendor's EFS and directories; its `0x62` entries name a copy of
the one reset image, and the FFS exists once, in the lower half
(docs/amd-sp3.md, "Flash image").

```sh
cargo fbuild build --board tyan-s8030 --release
cargo fbuild assemble --board tyan-s8030 --release        # -> tyan-s8030.rom
cargo fbuild assemble --board tyan-s8030 --release \
    --image-config /path/to/flash-backup.bin                # another vendor build
```

## Slot bifurcation

The vendor BIOS takes each x16 slot's bifurcation from its `Setup`
variable (`Setup[0x194..0x198]`, set in BIOS Setup; the BMC is not
involved). fstart has no settings store yet, so it is a build-time
choice. `tyan-s8030` keeps the vendor default (every slot x16); the
`tyan-s8030-pcie3-x4x4x4x4` variant bifurcates PCIE#3 x4x4x4x4 for an NVMe
carrier (the test bench).

```sh
cargo fbuild assemble --board tyan-s8030-pcie3-x4x4x4x4 --release --image-config ...
```

This is temporary: per-machine settings move to an fstart settings
record in flash, editable without a rebuild.

## Vendor ROM

Every supported half keeps its PSP/BIOS directories and blobs in place
(PSP, ABL, SMU, PMU and DXIO firmware, APCB). Supply the Tyan v4.04 dual
image (`8030V404.ROM`, 32 MiB, SHA-256 pinned in the sp3 workspace's
`firmware/donors/SHA256SUMS`) as `vendor/8030V404.ROM`, or pass the
board's own flash backup with `--image-config`. Neither is part of this
repository.

| | Tyan v4.04 | Test bench S8030GM2NE (Rome-only build) |
|---|---|---|
| Lower half | Rome: vendor EFS, directories to `0x54b000` | Rome: vendor EFS, directories to `0x50b000` |
| Upper half | Milan: vendor EFS, directories to `0x586000` | zeros, kept |
| Reset image (`0x220000` bytes, linked at `0x75de0000`) | `0xde0000` in each half | `0xde0000` |
| FFS | `[0x600000, 0xde0000)`, lower half only | same |

A Rome boot reads the FFS through ROM2; a Milan boot, from the upper half,
through the FCH ROM3 window above 4 GiB.

## SKUs: S8030GM2NE and S8030GM4NE-2T

The two SKUs run the same vendor image and this crate does not tell them
apart:

- GM4NE-2T adds an Intel X550-BT2 (2 × 10GBASE-T) on lanes 76–79. The
  lane map always describes that x4 port; on GM2NE nothing is attached and
  the link does not train.
- No strap, GPIO, EEPROM or IPMI value in the vendor firmware selects a SKU,
  and the SMBIOS data says S8030GM2NE on both (BOARD_S8030 §3).

Both have the AST2500 BMC, two i210 ports, five PCIe x16 slots, two
SlimSAS x8 (four NVMe x4), fourteen SATA ports (two connectors, three
SFF-8643) and two M.2 sockets (PCIe x4 or SATA, detected per socket).

## Layout

| File | Content |
|---|---|
| `src/dxio.rs` | lane map and OEM patches (bifurcation, speed, compliance, LAN, VGA, M.2, BMC Gen3 cap) |
| `src/gpio.rs`, `src/gpio/table.rs` | `$A10` pad table (generated), M.2 detect pads, Rome GPIO4/5 |
| `src/policy.rs` | DF, SMU, NBIO, CCX, DXIO policy and FCH power-failure / spread-spectrum values |
| `src/bmc.rs` | AST2500 LPC decodes, Super I/O, SCU, COM1 console, IPMI KCS, Tyan OEM M.2 query, ACPI inputs |

`src/gpio/table.rs` and `src/dxio/tuning.rs` are generated by
`.venv/bin/python -m tools.gen_board_s8030` in the sp3 analysis workspace.
